# Matriz E2E dos 18 serviços náuticos — 31/10/2026

## Objetivo e fonte

A matriz é gerada **automaticamente a partir do catálogo público real** pela rotina
`frontend/scripts/e2e-service-matrix.mjs`. Ela não duplica manualmente a lógica de
perguntas: enumera cada alternativa habilitada, respeita condições de exibição,
e chama a rota real `POST /api/services/:id/quote` para comprovar os formulários
previstos para a combinação escolhida.

Dados: conta descartável, nomes e endereços inventados porém plausíveis, CPF com
dígitos verificadores válidos destinado **somente a testes**, datas, telefones,
características de embarcações, número da CIR e outros campos compatíveis com
os modelos. Nenhum documento pessoal é enviado. A OpenAI permanece desligada,
e a ausência de débito de crédito é conferida pelo navegador.

## Critério de seleção e aprovação

Para cada serviço, a rotina enumera exaustivamente os valores permitidos,
exceto opções declaradas `unavailableOptions` e perguntas ocultas cujas
condições são falsas. As 347 combinações são submetidas à rota real de quote.

Para o Chrome, a rotina usa cobertura combinatória *pairwise*: preserva cada
alternativa, cada par de respostas simultaneamente aplicável, estados de
visibilidade de perguntas e cada assinatura distinta de conjunto de anexos.
Os cenários são realizados sem mock do backend, com Fastify, Nginx e
PostgreSQL descartável, e são considerados aprovados apenas depois do download
efetivo de todos os PDFs esperados. A suíte comprova ausência de débito nos
cenários sem análise por IA e confere largura mobile no primeiro caso de cada
serviço. Cada execução produz `MATRIZ_TESTES.md`, `MATRIZ_TESTES.json`,
`RESULTADOS.md` e `RESULTADOS.json`, além das amostras.

## Limites — não considerar homologação integral

1. Os **347** estados foram testados pelo contrato da API; os **138** selecionados
   foram percorridos no navegador. Não afirmar que todas as 347 combinações
   foram percorridas individualmente na UI.
2. Os campos preenchidos são os para os quais existem fixtures sintéticas
   plausíveis; outros permanecem em branco intencionalmente. Não foi feita a
   comprovação de todos os valores possíveis, limites máximos, impressão nem
   precisão de alinhamento de cada campo de cada PDF.
3. Não foram testados documentos pessoais reais, OCR/extração com OpenAI,
   cobrança real, concorrência de usuários ou execução em celular físico.
4. A validação de formato PDF não equivale à aceitação do anexo pela Marinha.

## Como repetir

No repositório, acesse **Actions → Matriz E2E completa (manual) →
Run workflow**, na branch com o script. A tarefa sobe Docker Compose com
PostgreSQL efêmero, instala Playwright apenas no runner, executa
`node frontend/scripts/e2e-service-matrix.mjs`, publica os resultados
e destrói containers/volumes ao terminar.

O workflow é **manual**, para evitar custo e tempo de instalação do navegador
em cada PR. A suíte normal do CI continua habilitada para mudanças na aplicação.
